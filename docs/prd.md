# Harc Soundscape — 产品需求文档（PRD）

> 版本：v0.1（网页预览 + 云端）  
> 定位：音箱端沉浸式自适应声景（对标 Endel），非语音引导冥想  
> 本期范围：网页预览端 + 云端内容/配置服务；音箱固件后续迭代

---

## 1. 产品概述

### 1.1 一句话

Harc 根据场景与环境，**实时拼出永不重复的功能声景**，覆盖睡眠、办公、氛围、放松；网页端用于内容与听感预览，云端负责内容包与个性化参数，音箱端负责本地混音播放。

### 1.2 目标用户

| 角色 | 诉求 |
|------|------|
| 终端用户 | 一键进入睡眠/专注/氛围/放松状态 |
| 内容/音效同学 | 在网页上预览模式参数与声景包 |
| 产品/运营 | 管理场景包上下架、默认参数 |
| 音箱固件团队 | 消费同一套云端配置与内容包协议 |

### 1.3 成功标准（本期）

- 网页可切换四模式并实时听到差异化预览声景
- 云端可下发模式配置、场景包元数据、引擎参数
- 断网假设成立：音箱侧仅依赖「已缓存包」（本期网页演示在线拉取）
- 文档可指导后续 2G 音箱端落地

## 2. 模式定义

| 模式 ID | 名称 | 用户目标 | 听感关键词 | 默认时长选项 |
|---------|------|----------|------------|--------------|
| `sleep` | 睡眠 | 入睡 + 维持 | 低频、慢、少事件、遮掩 | 30 / 60 / 480 min |
| `focus` | 办公 | 专注不吵 | 稳定脉冲、中等密度 | 25 / 50 / 90 min |
| `atmosphere` | 氛围 | 空间气质 | 可辨识场景感 | 无限（∞） |
| `relax` | 放松 | 降压恢复 | 柔和、空间感、缓慢起伏 | 10 / 20 / 45 min |

### 2.1 氛围 vs 放松

- **氛围**：环境像某个地方（雨夜、林间、咖啡馆感），偏装饰与场所感  
- **放松**：帮用户「下来」，有更明确的能量下降曲线与收束感  

资产与规则必须分开，禁止合并成单一「轻松」模式。

## 3. 信息架构（本期：网页预览）

```
预览页
├── 品牌 / 产品名
├── 模式选择（睡眠 | 办公 | 氛围 | 放松）
├── 场景包选择（该模式下的 packs）
├── 播放控制（开始 / 暂停、时长）
├── 实时参数面板（只读预览：能量、密度、节奏…）
└── 云端状态（当前 pack、版本）
```

**不做（本期）：** 账号体系完整化、支付订阅 UI、音箱配对、复杂对话。

## 4. 用户故事

1. 作为产品同学，我打开网页，点「睡眠」，几秒内听到低频缓慢声景，确认与办公模式听感明显不同。  
2. 作为音效同学，我切换同一模式下不同场景包，确认纹理/事件密度变化符合预期。  
3. 作为固件同学，我调用云端 API 拿到 `engine_profile` 与 pack 清单，协议与网页预览一致。

## 5. 功能需求

### 5.1 网页预览端（P0）

| ID | 需求 | 优先级 |
|----|------|--------|
| W1 | 四模式切换，切换时平滑过渡（≤2s 淡入淡出） | P0 |
| W2 | 基于 Web Audio 的多层实时预览（模拟 stem 混音） | P0 |
| W3 | 展示云端下发的模式参数（能量/密度/节奏等） | P0 |
| W4 | 时长选择；睡眠/放松支持收束；氛围支持无限 | P0 |
| W5 | 场景包列表来自云端，可切换 | P0 |
| W6 | 移动端可播可切模式 | P1 |

### 5.2 云端（P0）

| ID | 需求 | 优先级 |
|----|------|--------|
| C1 | `GET /modes` 返回四模式定义与默认参数 | P0 |
| C2 | `GET /packs?mode=` 返回场景包列表 | P0 |
| C3 | `GET /packs/{id}` 返回引擎 profile + 层描述 | P0 |
| C4 | `GET /health` 健康检查 | P0 |
| C5 | 静态/对象存储预留：未来真实 stem 文件 CDN | P1 |
| C6 | 个性化参数下发（用户偏好） | P2 |

### 5.3 内容包（Pack）模型

- 每个 Pack 隶属一个 `mode`
- 包含：`id`、`name`、`description`、`engine_profile`、`layers[]`
- 本期网页用 **程序化层**（振荡器/噪声）模拟；音箱端替换为真实 stem 文件 URL

## 6. 交互与视觉原则

- 首屏即品牌 + 当前模式 + 一个主播放动作（非仪表盘堆砌）
- 氛围感背景随模式变化（睡眠偏深夜、办公偏冷静、氛围偏场景色、放松偏柔和）
- 禁止卡片墙、统计条、多块营销信息抢首屏
- 至少 2–3 处有意动效：模式切换、播放态呼吸、参数微动

## 7. 商业与内容（前瞻）

| 层级 | 内容 |
|------|------|
| 出厂 / 免费 | 四模式各 1 个默认 Pack |
| 订阅 / 增值 | 联名、季节、题材扩展包 |
| 硬件形态 | 同一云端协议；不同音箱用 EQ/默认模式/按键映射区分 |

本期网页不实现付费，仅预留 `tier: free | premium` 字段。

## 8. 非目标（本期 / 第一步明确不做）

- 音箱固件 / 2G 端混音落地（属第一步后半段，见里程碑）
- **模型相关（一律放到第二步）**：推荐模型、意图 LLM、偏好学习、端侧分类、AI 辅助做 stem 等
- 本地大模型或云端实时 AI 作曲主路径（即使第二步也不作为实时发声主引擎）
- 语音对话式冥想引导
- 心率等可穿戴强依赖

## 9. 里程碑（已拍板：模型放第二步）

| 步骤 | 阶段 | 交付 | 模型 |
|------|------|------|------|
| **第一步** | M0（当前） | PRD + 技术规格 + 网页预览 + Go 云端 API | 不做 |
| **第一步** | M1 | 真实 stem 管线 + CDN + 包下载；调音金样 | 不做 |
| **第一步** | M2 | 音箱端引擎对接同一 API；时间/基础自适应 | 不做 |
| **第二步** | M3 | 云端模型：推荐、偏好、意图→参数；可选噪声分类 | **开始做** |
| **第二步** | M4 | 模型辅助离线内容生产（人审+调音入库）；声光/可穿戴等增强 | 增强 |

**原则：** 第一步用 stem + 规则引擎做出稳定 Endel 感；第二步再让模型写回「小结果」（pack / profile 微调），不替换实时混音主路径。
